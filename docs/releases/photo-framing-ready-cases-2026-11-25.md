# Frame saved watch photos and publish eligible cases

Reviewers can rotate a cutout proposal, adjust its size, reset the frame and inspect it enlarged before saving. The complete watch stays centered on a white canvas. The selected framing is derived from the saved proposal, and the original image and restore history remain available. Rotation and resizing resample the existing image; they do not regenerate watch markings or retouch wear.

The save-and-replace action remains visible. Reopening a partially saved result retains its framing for a safe retry. Archived photographs are read-only, with a clear instruction to reopen the current case. If an active image is unchanged but its review metadata moved on, an explicit request can reuse the cached cutout against a fresh review revision. A free-only reuse request cannot turn into a paid job when the source changes or the cached result is unavailable.

Authorized Repair marketplace managers can publish approved cases after existing identity, price and listing gates. Identity viewing is restricted to allocated marketplace reviewers and closes after their decision. Pending review and missing documents are explained separately.

The update is installed. Validation included 184 repository checks, 37 synthetic raster/input checks, 80 review/authorization checks and 252 shared-editor interactions across phone/desktop light/dark states. Paired Repair checks covered deliberate confirmation and keeping a case open when the photo editor closes. Native read-only verification generated rotated PNGs in memory from existing proposals without saving or accepting them. No customer photo, identity decision or listing was accepted/published for testing, and no paid model call or worker restart was required. Natural-photo acceptance remains the reviewer's decision.


## Saving reviewed images reliably

A shared upload optimizer could convert a reviewed PNG during saving, causing the replacement integrity check to reject it. The installed correction preserves only the verified generated file while normal uploads continue to optimize. Checksums remain enforced. Existing ready previews can be saved without another provider request; idempotency and restoration remain available.

198 paired repository/raster checks exercise the actual optimizer with detailed images, framed replacement, normal compression, one attachment, repeated save and restoration. Native source hashes, current versions and allowed/denied access were verified without accepting a real photo. Repair staff can also reject a challenged background explicitly and return the photo for correction without falsely confirming a white background.


## Review identity inside the Repair case

Marketplace 0.165.8 provides separate identity and publication readiness controls to allocated Repair marketplace reviewers. Waiting and returned cases can show submitted identity evidence before watch approval. Reviewers can approve valid evidence or reject it with a reason; after a decision the document viewer closes and old document access is denied. Missing or invalid evidence cannot be approved.

The publication control explains outstanding identity, price, photo and listing conditions. It rechecks current evidence before publishing. Status-only case responses contain no private document links. The dedicated document endpoint retains evidence-revision and reviewer checks, while unrelated global administration access remains unchanged.

Installed with Repair 2.17.11. The service/database suite passes 102 checks, with separate identity-decision and input-consistency regression checks. 76 shared interface assertions cover phone/desktop light and dark states, including rejection reasons, closing documents and publication confirmation. Release verification was read-only; no real identity or listing decision was created for testing.
